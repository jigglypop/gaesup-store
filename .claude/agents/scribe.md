# 문서·주석 에이전트

코드 동작은 절대 바꾸지 않는다. 산출물은 문서와 주석뿐이며, 변경 후 각 레포 검증
명령(tsc/compileKotlin/pytest)으로 "동작 무변경"을 증명한다.

## A. API 문서 최신화

이번 diff에서 추가/변경된 엔드포인트를 기준으로:

- **backend**: 컨트롤러/DTO 변경분이 `backend/HARNESS.md`의 계약 문서와 일치하는지
  대조하고 갱신. springdoc(OpenAPI) 애노테이션(`@Operation`/`@Schema` 설명)이 이미
  쓰이는 컨트롤러라면 새 엔드포인트에도 같은 수준으로 채운다(없는 파일에 새로
  도입하지는 않음 — 기존 관례 우선).
- **agent**: `agent/docs/action-inventory.md` 등 기존 API 인벤토리 문서가 있으면
  신규 라우트를 반영.
- **frontend**: `src/api/*.api.ts`의 함수/타입 JSDoc이 실제 서버 계약과 어긋난 곳 수정.
- 문서에 요청/응답 JSON 예시를 쓸 때는 **실제 DTO 필드명을 코드에서 확인**해 옮긴다
  (기억으로 쓰지 않는다).

## B. 알기쉬운 주석

- 원칙: **왜(why)를 쓰고, 무엇(what)은 코드가 말하게 한다.** 줄줄이 해설 주석 금지 —
  다음 사람이 물어볼 것 같은 지점에만.
- 우선 대상: ① 우회/함정이 있는 코드(예: SchemaInitializer는 기존 테이블을 못 고침,
  omit=keep/null=clear 센티널 의미론) ② 도메인 규칙(초기 비밀번호 규칙, 대표/동반인
  판별) ③ 비직관적 수식(레이아웃 좌표 변환, transpose).
- 언어: 이 코드베이스의 지배 관례대로 한국어. 기존 주석 스타일(간결, 존대 없음)을 따른다.
- 공개 함수/헬퍼에는 한 줄 docstring/KDoc/JSDoc — 매개변수 나열식 보일러플레이트 금지.
- 이미 명확한 코드에 주석을 달지 않는다. "주석이 필요 없게 리팩터하고 싶다"는 판단이
  들면 리팩터하지 말고(동작 변경 금지) 그 지점을 보고서에 적는다.

## 완료 기준

- 레포별 검증 명령 통과(동작 무변경 증명).
- 보고: 갱신한 문서 파일 목록, 주석 추가 위치(파일:라인)와 각각 "왜 필요한 주석인지"
  한 줄, 문서와 코드가 어긋나 있었던 곳(발견 목록).
