# /harness — 품질 파이프라인

`.claude/ORCHESTRATION.md`의 표준 파이프라인을 실행한다. 인자가 없으면 전체
(all 레포, 전 단계). 예: `/harness frontend qc`, `/harness backend qc test`.

## 절차

1. **범위 확정**: 레포별 `git status --short`/`git diff --stat`로 변경분을 파악한다.
   변경이 없는 레포는 대상에서 제외하고 사용자에게 알린다.
2. **QC 라운드**: 변경이 있는 레포마다 `qc` 에이전트를 병렬로 실행(읽기 전용).
   프롬프트에 diff 범위와 스택별 검증 명령을 명시한다.
   - 치명/버그 발견 시: `dev` 에이전트(대상 레포 명시)에
     수정을 위임하고 qc를 재실행한다. 통과할 때까지 다음 단계로 넘어가지 않는다.
3. **테스트 라운드**: `test-writer`를 레포별로 실행(frontend는 러너가 없으므로 제외).
   이번 diff에서 새로 생긴 분기를 프롬프트에 나열해준다.
4. **품질 라운드**: `quality`(코드량+성능)를 레포별 병렬 실행. 각 레포 HARNESS.md의 기존
   백로그(발견됐지만 미적용 항목)가 있으면 프롬프트에 우선 적용 대상으로 전달한다.
5. **종합 보고**: 단계별 결과(발견/수정/감소량/수치)를 심각도·레포 순으로 정리하고,
   각 레포 HARNESS.md에 라운드 기록이 append됐는지 확인한다. 커밋은 사용자 승인 후.

## 주의

- 같은 레포에 쓰기 에이전트 2개를 동시에 띄우지 않는다.
- 에이전트가 비정상 종료(메타 발언만 반환, 토큰 수 이상)하면 `git status`로 실제
  변경 여부 확인 후 재실행.
- 사전 존재 실패는 각 단계에서 별도 표기하게 하고, 이번 라운드 탓으로 오인하지 않는다.
